## Блок 1. Теория вероятности и логика

### 1. Фермер

Считаю, что при каждом посещении животное каждого из шести видов появляется с одинаковой вероятностью `1/6`, а посещения независимы. Для каждого вида введём индикатор: увиден ли он хотя бы один раз. Вероятность не увидеть фиксированный вид за шесть посещений равна `(5/6)^6`. По линейности математического ожидания:

```text
E = 6 * (1 - (5/6)^6) = 3.990612...
```

**Ответ: 3,99.**

### 2. Кулинарное соревнование

Пронумеруем участников от 1 (самый слабый) до 80 (самый сильный). У участника с номером `i` есть `i - 1` более слабых возможных соперников, поэтому вероятность выиграть один этап равна `(i - 1) / 79`. Паросочетания двух этапов независимы, хотя конкретная пара может повториться. Вероятность выиграть оба этапа - квадрат этой величины.

```text
E = sum(k^2 / 79^2, k=0..79)
  = 80 * 159 / (6 * 79)
  = 26.835443...
```

**Ответ: 26,8.**

### 3. Одинокая дорога

Ответ однозначен при стандартном предположении о стационарном пуассоновском потоке автомобилей. Если `P(N(30) >= 1) = 0.95`, то `P(N(30) = 0) = 0.05`. Для интервала `t`:

```text
P(N(t) >= 1) = 1 - 0.05^(t / 30).
```

- 10 минут: `1 - 0.05^(1/3) = 0.631596...`;
- 27 минут: `1 - 0.05^0.9 = 0.932536...`.

**Ответ: 63,2; 93,3.**

Без предположения о характере процесса одной вероятности за 30 минут недостаточно, чтобы восстановить вероятности за другие интервалы.

## Блок 2. Python

Полный код находится в [`solutions.py`](solutions.py), тесты - в [`tests/test_solutions.py`](tests/test_solutions.py).

### 1. Изоморфизмы

```python
def is_isomorphic(s: str, t: str) -> bool:
    if len(s) != len(t):
        return False

    s_to_t = {}
    t_to_s = {}
    for source_char, target_char in zip(s, t):
        if source_char in s_to_t and s_to_t[source_char] != target_char:
            return False
        if target_char in t_to_s and t_to_s[target_char] != source_char:
            return False
        s_to_t[source_char] = target_char
        t_to_s[target_char] = source_char
    return True
```

Два словаря одновременно обеспечивают однозначность отображения в обе стороны. Сложность: время `O(n)`, дополнительная память `O(k)`, где `k` - число различных символов (в худшем случае `O(n)`).

### 2. Натуральная последовательность

```python
def missing_number(nums):
    n = len(nums) + 1
    missing = 0
    for value in range(1, n + 1):
        missing ^= value
    for value in nums:
        missing ^= value
    return missing
```

Одинаковые числа при XOR взаимно уничтожаются, остаётся отсутствующее число. Сложность: время `O(n)`, дополнительная память `O(1)`. Предполагаются условия задачи: элементы уникальны, принадлежат `1..n`, отсутствует ровно один элемент.

### 3. Факторизация

```python
def prime_factors(n: int) -> list[int]:
    if n < 1:
        raise ValueError("n must be a positive integer")

    factors = []
    while n % 2 == 0:
        factors.append(2)
        n //= 2

    divisor = 3
    while divisor * divisor <= n:
        while n % divisor == 0:
            factors.append(divisor)
            n //= divisor
        divisor += 2

    if n > 1:
        factors.append(n)
    return factors
```

Проверяются только 2 и нечётные делители не больше квадратного корня от текущего остатка. Худшее время `O(sqrt(n))`; вспомогательная память `O(1)`, не считая выходного списка `O(log n)`.

## Блок 3. SQL

Запросы приведены в [`solutions.sql`](solutions.sql). Синтаксис - PostgreSQL.

### 1. Абитуриенты

```sql
SELECT
    id,
    scores,
    RANK() OVER (ORDER BY scores DESC NULLS LAST) AS rating_position
FROM examination
ORDER BY rating_position, id;
```

При одинаковом количестве баллов абитуриенты делят позицию, а следующая позиция пропускается, как в спортивном рейтинге. `NULLS LAST` не позволяет отсутствующему результату оказаться выше реальных баллов. Если позиции без пропусков являются бизнес-требованием, следует заменить `RANK()` на `DENSE_RANK()`.

### 2. FULL JOIN

**Ответ: минимально 30 и максимально 600 строк.**

- Минимум - 30: все 20 строк второй таблицы могут сопоставиться с 20 из 30 строк первой, остальные 10 строк первой останутся без пары. FULL JOIN не может вернуть меньше строк, чем содержит большая таблица.
- Максимум - `30 * 20 = 600`: если у всех строк обеих таблиц один ключ, каждая строка первой таблицы соединится с каждой строкой второй.
- Если все ключи в обеих таблицах абсолютно уникальны и не совпадают, получится 50 строк, но это не глобальный максимум.

### 3. Покупки

```sql
SELECT
    a.client_id
FROM account AS a
JOIN "transaction" AS t
    ON t.account_id = a.id
WHERE t.type = 'PUR'
  AND t.transaction_date >= CURRENT_DATE - INTERVAL '1 month'
  AND t.transaction_date <= CURRENT_DATE
GROUP BY a.client_id
HAVING SUM(t.amount) < 5000
ORDER BY a.client_id;
```

Основной запрос следует буквальной формулировке «совершили покупки», поэтому клиенты без покупок не попадают в результат. Приняты допущения: код покупки - `'PUR'`, а «последний месяц» - скользящий интервал от текущей даты на месяц назад. Если по бизнес-правилу ноль покупок тоже считается суммой меньше 5000, нужен `LEFT JOIN`, фильтры транзакций следует перенести в `ON`, а сумму записать как `COALESCE(SUM(t.amount), 0)`. Если имеется в виду предыдущий календарный месяц, границы дат нужно заменить на `date_trunc('month', CURRENT_DATE) - INTERVAL '1 month'` и `date_trunc('month', CURRENT_DATE)`.

## Блок 4. Статистика и A/B-тесты

### 1. Воодушевлённое руководство

**Выбираю утверждения 2 и 4.**

- Тест в одном небольшом городе не обосновывает масштабирование на всю страну: внешняя валидность ограничена.
- Результат подтверждает потенциал идеи в исследованной среде, поэтому разумный следующий шаг - повторить эксперимент в городах разных типов, заранее определить сегменты и проверить операционные ограничения.
- Утверждение 1 неверно: одинаковое абсолютное число изменённых транспортных средств не решает проблему переносимости эффекта.
- Утверждение 3 нельзя принять без дополнительных данных: один город не является репрезентативной выборкой всех похожих небольших городов. Переносимость эффекта нужно подтвердить повторными тестами и сопоставимостью населения, инфраструктуры, спроса, сезона и логистики.

### 2. Основной показатель в статистике

**Верный вариант: вероятность наблюдения такого или более экстремального результата при условии, что нулевая гипотеза верна.**

p-value не является вероятностью истинности нулевой гипотезы. Это вероятность данных (или более экстремальных данных) при `H0`, а не вероятность `H0` при данных.

### 3. Параметрический тест

**Да, при описанных условиях можно применить двухвыборочный t-тест, предпочтительно критерий Уэлча.**

При более чем 5 млн независимых наблюдений в каждой группе центральная предельная теорема обеспечивает близкое к нормальному распределение выборочного среднего даже при логнормальной индивидуальной метрике, если её дисперсия конечна. Отсутствие значительных выбросов дополнительно снижает риск нестабильности.

Перед применением необходимо проверить:

- рандомизация и независимость наблюдений;
- единица анализа совпадает с единицей рандомизации (пользователь);
- пользователи не попадают в обе группы;
- нет кластерной зависимости или повторных наблюдений, игнорируемых тестом;
- дисперсии оцениваются раздельно - поэтому Welch надёжнее pooled t-test.

При больших выборках даже очень малый эффект может стать статистически значимым, поэтому вместе с p-value нужны размер эффекта и доверительный интервал.

## Блок 5. ML Base

### 1. Пони тоже кони

Сначала проверю одинаковость валидационной выборки, отсутствие утечки и правильность кодирования положительного класса. При корректной проверке перспективнее **вторая модель с ROC-AUC = 0,1**: она почти идеально ранжирует классы в обратном порядке. Инвертирую скор (`p_new = 1 - p` либо `score_new = -score`), после чего ROC-AUC станет `1 - 0,1 = 0,9`. Затем повторно проверю метрику на независимой отложенной выборке и откалибрую вероятности. Если инверсия возникла из-за ошибки в метках или pipeline, сначала исправлю первопричину; нельзя слепо выбирать модель только по числу.

### 2. Ручной счёт ROC-AUC

ROC-AUC не зависит от выбранного порога 0,6: используются оценки вероятности при всех возможных порогах. Есть 7 положительных и 8 отрицательных объектов, то есть 56 пар «положительный-отрицательный».

Число отрицательных объектов с меньшей оценкой для положительных объектов по убыванию score:

```text
8 + 7 + 6 + 6 + 6 + 6 + 3 = 42.
```

Совпадающих оценок между классами нет, поэтому:

```text
ROC-AUC = 42 / (7 * 8) = 0.75.
```

**Ответ: 0,75.**

### 3. Ручной счёт корреляции

Средние значения: `x_bar = 2,3` чашки и `y_bar = 73,2` балла. Для коэффициента Пирсона:

```text
sum((x - x_bar)(y - y_bar)) = -93.6
sum((x - x_bar)^2) = 8.1
sum((y - y_bar)^2) = 1499.6

r = -93.6 / sqrt(8.1 * 1499.6) = -0.84927...
```

**Ответ: -0,85.** В этой небольшой выборке наблюдается сильная отрицательная линейная связь: большее количество кофе связано с более низким баллом. Причинно-следственную связь утверждать нельзя. Это наблюдательные данные; возможны смешивающие факторы - недосып, стресс, исходная подготовка, здоровье - и обратная причинность: менее подготовленные или более уставшие студенты могут пить больше кофе.
